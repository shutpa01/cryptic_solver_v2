# Clue checker + anonymous Ask Us — research notes (2026-10-21)

Discussion only. Nothing has been built.

## 1. The idea

Reddit has a large community that writes its own cryptic clues. The idea is a standalone tool
where a setter submits a clue and its answer, it runs through our solver, and the narration (prose)
explains it, or says simply why it doesn't work. Pendings are assumed to be OK.

**What already exists and costs nothing:**
- The cascade and signature solver are mechanical. The setter gives the answer, so the tool only
  has to check a reading, not find one.
- The gate checks give "why it fails" reasons: fodder letters don't match, the indicator isn't a
  known one, the definition isn't at an end of the clue, a word is unused, a letter is invented.
- `scripts/narrate_clue.py` `narrate()` builds the explanation from templates, with no model call.

**What costs money:**
- The prose drafter (`scripts/draft_prose.py`) is the step that checks whether the meaning holds,
  including weak synonyms in pendings. That's its proven strength: the user's 10-11 verdict was that
  the prose has been excellent at catching false passes from WFW.
- It is a Claude call.

**Decisions and constraints:**
- The Claude subscription (`claude.exe -p`) must not power a public tool. I believe the consumer
  terms don't allow it; not verified. A public tool needs the API.
- **API cost estimate:** about 1,200 tokens in (PROMPT_HEAD is 3,433 characters, plus the facts)
  and about 150 out, roughly $0.006 per clue on a Sonnet-class model, so about $6 per 1,000 clues.
  Haiku-class would be about a third of that. Prices not verified. Needs a hard daily cap.
  User: "we could probably manage that."
- **Wording rule:** say "we couldn't find a reading", never "unsound". Our reference database has
  gaps.
- **Untested:** every success so far has been on edited newspaper clues. Suggested pilot: run 20–30
  Reddit clues by hand through the existing Custom section (`/custom/clues/`).
- All processing runs on the local PC today, so a standalone tool needs the solver and the
  reference database wherever it runs.

## 2. The delivery model: Up and Cycling "Ask Us"

The user proposed using the anonymous model already built for Up and Cycling
(`C:\Users\shute\trainer-proof\support\`, README.md, worker.js, wrangler.toml):

- The question goes to a Cloudflare Worker, which emails it to the support inbox with a ticket
  number.
- The **device keeps the ticket number itself**, so the user has no code to keep, no email to give,
  and nothing to download (the user rejected a private code).
- Our Gmail reply goes to ticket@reply… through Cloudflare Email Routing and is stored in Workers KV
  (`SUPPORT_REPLIES`, answers only, deleted after 60 days).
- The app shows "We've replied". It is rate-limited to 5 a minute by IP, held in memory only.
- For a web page, the browser would hold the ticket instead of the app.

**Other points:**
- **No per-customer domains needed.** One domain and one Worker serve every customer (for example
  `/c/xytv479`), and one reply address carries the customer and ticket in the subject. Separate
  domains would cost about $10 a year each and hurt mail reputation.
- **Live chat is not our market** (user).
- **Harder parts than the code:** spam on an anonymous inbox, setup for each customer, and keeping
  "we hold nothing" true.

## 3. Is anyone else doing it? (web search, 2026-10-21)

No product was found with the full pattern: a ticket held on the device, no code, no email, and
replies from ordinary email. This is not proof that none exists.

| Product | Email from user? | User keeps a code? | Two-way | Cost (review sites, may be stale) |
|---|---|---|---|---|
| Ask Us (ours) | No | No | Yes | no new subscription (estimate) |
| Incogneato | No | Yes, a return code | Yes | ~$17–$83/month, free version |
| Anonymeter | No | Revisits the form link (mechanism undocumented) | Yes | not found |
| Zendesk | Usually; verification required from Mar 2026 (no-email requests are exempt, mechanism unclear) | — | Yes | ~$55–$115 per agent per month |
| Customer.io | No | — | One way only | from ~$100/month |
| GhostChat | No | Live chat only | While online | free, then ~$5–$25/month |

A Zammad community thread asks for exactly this, with no solution:
https://community.zammad.org/t/anonymous-tickets/12246

**Where the others are ahead:** team features (Zendesk) and website use without an app. Also, if
the user clears the app or changes phone, an unanswered ticket is lost.

**User's view:** these are cheap wrappers with no new technology; we could do it better and cheaper.

## 4. Cloudflare limits at high traffic (from memory, NOT verified)

- **Free plan:** about 100,000 Worker requests per day, and KV reads of a similar order.
- Ask Us polls every 15 minutes, about 96 reads per active device per day. The free plan therefore
  covers roughly 1,000 always-open devices.
- **$5/month Workers paid plan:** about 10 million requests per month.
- A clue checker web page would poll only while it's open, so far fewer reads.
- Check Cloudflare's current pricing page before relying on any of this.
